The question for the next 40 minutes

How do you get a computer — which only does arithmetic — to decide that two sentences with no words in common mean the same thing?

Start with something you already know

How does a computer store a colour?

255, 0, 0 red
254, 2, 1 also red

Nobody told it these are both red. It falls out of the numbers being close together. A human concept became coordinates, and closeness became similarity.

Now do it for words · start with one dimension

Give every word a single number.

So add a second dimension
The real thing

384 dimensions. And nobody designed them.

The model was trained on an enormous amount of text with one stupidly simple job: guess the missing word. To get good at that, it had to invent its own internal dimensions of meaning.

Dimension 137 doesn’t say “food-ish”. It says 0.0413, and nobody knows exactly why.

Those learned coordinates are an embedding.

Now we need a measuring tape
Cosine similarity
Let’s do it by hand · 2 dimensions: access-ish, food-ish
"log in" = [0.9, 0.1] "sign in" = [0.8, 0.2] "pizza" = [0.1, 0.9] cos(A,B) = (A · B) / (|A| × |B|) log in vs sign in log in vs pizza A · B = 0.9×0.8 + 0.1×0.2 = 0.74 A · B = 0.9×0.1 + 0.1×0.9 = 0.18 |A| = √(0.81+0.01) = 0.906 |A| = 0.906 |B| = 0.906 |B| = √(0.64+0.04) = 0.825 cos = 0.74 / 0.747 = 0.99 cos = 0.18 / 0.82 = 0.22
0.99log in / sign in
0.22log in / pizza

Multiply, add, divide. That’s the whole algorithm — and not one shared letter did any work.

One gap left

Can we just average the word vectors?

dog bites man → avg(dog, bites, man) man bites dog → avg(man, bites, dog) ← identical

Two very different days.
One vector.

Averaging throws away word order — and a lot of meaning lives there. So we use a model that reads the sentence as a sentence and emits one vector for the whole thing.
